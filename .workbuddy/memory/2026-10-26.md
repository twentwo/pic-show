# PicShow 项目日志

## 2026-10-26

完成 Tauri 2 跨平台照片查看器（复刻 Google Picasso 体验）的全部实现与验证。

### 技术选型（已定稿，勿回退）
- 图片传输走**自定义异步 `img://` 协议**，不走 IPC + base64（后者体积 +33% 且阻塞主线程）。
- 前端**零打包器**：`ui/` 为纯静态资源，`ui/js/*.js` 是原生 ES Module，由 Tauri 直接加载；
  `ui/js/tauri.js` 手写 IPC 封装，不依赖 `@tauri-apps/api`。
- 网格用 **justified 等高行**，不用方形九宫格——后者需 `object-fit: cover` 裁图，
  会让 FLIP 转场因宽高比失配而跳变。
- 网格与全屏查看器**共用同一个缩略图 URL**（`THUMB_SIZE` 由 `GRID_ROW_H` 推导），
  保证点开大图时低分辨率底图必命中缓存。

### 本轮修复的跨文件不一致（易复发，改动时留意）
1. `viewer.js` 用 `.nav-prev` / `.nav-next`，而 HTML 是 `.nav-btn.prev` / `.nav-btn.next`
   —— 已统一为后者。
2. CSS 里 `.chrome` / `.nav` / `.nav-prev` / `.nav-next` 与 HTML 的
   `.viewer-chrome` / `.nav-btn` / `.prev` / `.next` 命名分叉 —— 已统一为 HTML 命名。
   若漏改，左右导航按钮会同时堆到左上角（定位规则失效）。
3. 空状态 HTML 用 `.hint-list`，CSS 只有 `.shortcuts` —— 已改 HTML 为 `.shortcuts`。
4. `.viewer-stage` 铺满全屏会吃掉背景点击，导致「点图片外关闭」永不触发
   —— 已加 `pointer-events: none`，`.slide` 用 `auto` 恢复。
5. `#cache-text` 原本没有任何数据源 —— 已在 `main.js` 接上 `cache_stats` 命令。
6. 关闭动画期间手势未冻结会打断 FLIP —— `close()` 开头置 `g.enabled = false`。

### 关键 bug：窗口永远不显示（已修）
`tauri.conf.json` 里窗口配 `visible: false`（为避免 webview 首帧白闪），
但 `lib.rs` 里**从来没有调用 `show()`** —— 结果 `npm run dev` 跑起来后
窗口一直隐身，用户看不到任何东西，误以为要去浏览器打开 `:1420`，
于是点到「无法调用命令：pick_images」的报错。

修复：
- `commands.rs` 新增 `window_ready` 命令 + `reveal_main_window()`（show + set_focus）。
  用自定义命令而非内置 `plugin:window|show`：应用自带命令不走 capabilities 校验。
- `lib.rs` setup 里另起线程，3 秒后若窗口仍不可见则强制显示，作为兜底
  （防止前端脚本报错导致永远不上报就绪）。
- 前端 `main.js` 末尾调 `api.showWindow()`。

### 另一处易误用：浏览器打开 :1420
`:1420` 只是 `beforeDevCommand` 起的静态服务器，专供 Tauri 内部 webview 加载前端。
普通浏览器没有 `__TAURI_INTERNALS__` 注入，命令不可用。
`main.js` 的 `applyHostMode()` 会在非 Tauri 环境下禁用全部入口按钮并显示
`#host-warning` 提示条，避免误点。

### 关键 bug：选择了图片后界面无反应（已修）
**症状**：弹窗能出、选完图片后界面无反应，右上角显示「没有找到支持的图片」。

**排查路径（关键经验）**：先排除后端——用 `open_paths` 直接扫 `/tmp/picshow-test`
（3 张真图），确认 `expand` / `register` / `emit` 全通；再确认 TCC 不背锅
（`~/Desktop` expand=5、`~/Pictures` expand=352，只有 `Photos Library.photoslibrary`
因系统保护被拒，属正常）；最后用「事件往返探针」定位：
后端 `emit` 一个已知 payload → 前端记录收到的形状 → 发现收到的是
`{event, payload:{...}}` 整个包装对象。

**根因**：手写的 `tauri.js listen()` 里多包了一层。Tauri 桥接脚本
（`tauri-2.x/src/event/mod.rs` 的 `emit_js_script`）给回调传的已经是
完整事件对象 `{event, payload, id}`，`listen()` 又把它裹成
`{event, payload: eventData, id}` 传给 `api.js` 的
`(event) => handler(event.payload)` —— 于是 handler 拿到的是包装对象本身，
`payload.items` 恒为 `undefined` → 列表恒空 → 「没有找到支持的图片」。

**修复**：`listen()` 回调改为 `handler({ event, payload: eventData?.payload, id })`。

**教训**：手写 IPC 封装时，事件回调的参数形状必须实证（往返探针），
不能靠猜。这条已写进 README FAQ。

**附带教训——清理临时诊断代码不要用「切片截断」**：
曾用 `s.index('TEMP DIAG')` 到文件尾的方式清理 `api.js`，误删了
`onItems` 和 `preload` 两个导出。应使用精确的 Edit 操作，删完跑
`node /tmp/picshow_check.mjs` 交叉校验导出完整性。

### 关键 bug：手势与快捷键全部失效（已修）
**症状**：打开文件夹后图片能显示，但全屏查看器里拖拽、滚轮、双击、方向键全无反应。

**根因**：`ui/js/viewer.js` 调用了 `this.bumpControls()` 共 5 次（`open()` 末尾、
`go()` 中、`onTap`、`onUserActivity` 回调），但**这个方法从未定义**。

致命之处在于调用位置（最容易被忽略的一环）：
```js
onPointerDown(event) {
  if (!this.enabled) return;
  this.o.onUserActivity?.();   // → 就是 bumpControls，这里先抛异常
  this.pointers.set(...);      // → 永远执行不到，指针没被登记
}
```
`onPointerMove` 开头 `if (!this.pointers.has(id)) return;` —— 于是**所有手势全死**。
键盘侧：首次方向键能让 `go()` 走到 `bumpControls()` 抛错，导致
`previous.remove()` 与 `this.switching = false` 都不执行，切换**永久卡死**。

**修复**：补上 `bumpControls()`（清旧计时器 → 移除 `is-idle` → 重新定时 `IDLE_MS`
后加回 `is-idle`，并校验仍处于打开态）。

**防复发**：新增 `tools/check_methods.mjs`，静态扫描 `ui/js/*.js`，
核对 (1) 所有 `this.x()` 调用都有对应定义；(2) 所有具名导入的符号
确实被目标模块导出。已接进 `npm run check`（`cargo check` + 几何测试 + 本检查）。

> 为什么必须靠工具拦：前端是零打包器原生 ESM，打包期不会报错，
> 「方法未定义」只会在运行到那一行时才炸，表现为「按钮没反应」这类
> 无因果可循的静默故障。这已经是本项目第二次栽在同类问题上
> （前一次是 `api.js` 导出被误删）。

### 双指左右滑动切换：已实现后回退（2026-10-26 用户判定「效果不太好」）
回退方式：手工逐项撤销（项目无 git、也无该文件备份）。
教训 —— **本项目应尽早建 git 仓库**，否则「回退到上一版本」只能靠记忆精确还原。

若日后重做，两个关键坑（当初踩过）：
1. 横滑**不能走 `settle()`**：`scale <= 1` 时 `panBounds` 的 maxX 为 0，
   `settle()` 会把已阻尼过的位移再压一次（二次阻尼），手感发死。
2. **wheel 与 pointer 的横向符号相反**：触控板两指向左滑 → `deltaX > 0`；
   触屏两指向左滑 → 中点 `mid.x` 减小。必须统一符号后再累积。
3. 触控板两指横滑在 WKWebView 里是**一串带 deltaX 的 wheel 事件**（非 pointer），
   需另用「累积 + 静止判定」模拟按下-移动-松手。

**回退时保留了两处独立 bug 修复**（与横滑无关，撤销会重新引入问题）：
- `gestures.js springBack()`：`scale < 1` 时回弹到 1。捏合缩小到 0.5 松手后
  原本会一直停在 0.5，违反「越界自动回弹」。
- `viewer.js syncOrigin(index)`：切换图片后把 `originEl` 挪到新索引对应的格子。
  否则关闭动画会飞回**旧图**位置，且旧缩略图一直隐形。
