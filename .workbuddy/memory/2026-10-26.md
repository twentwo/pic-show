# PicShow 项目日志

## 2026-10-26

完成 Tauri 2 跨平台照片查看器（复刻 Google Picasso 体验）的全部实现与验证。

### 技术选型（已定稿，勿回退）
- 图片传输走**自定义异步 `img://` 协议**，不走 IPC + base64（后者体积 +33% 且阻塞主线程）。
- 前端**零打包器**：`ui/` 为纯静态资源，`ui/js/*.js` 是原生 ES Module，由 Tauri 直接加载；
  `ui/js/tauri.js` 手写 IPC 封装，不依赖 `@tauri-apps/api`。
- 网格用 **justified 等高行**，不用方形九宫格——后者需 `object-fit: cover` 裁图，
  会让 FLIP 转场因宽高比失配而跳变。
- 网格与全屏查看器**共用同一个缩略图 URL**（`THUMB_SIZE` 由 `GRID_ROW_H` 推导），
  保证点开大图时低分辨率底图必命中缓存。

### 本轮修复的跨文件不一致（易复发，改动时留意）
1. `viewer.js` 用 `.nav-prev` / `.nav-next`，而 HTML 是 `.nav-btn.prev` / `.nav-btn.next`
   —— 已统一为后者。
2. CSS 里 `.chrome` / `.nav` / `.nav-prev` / `.nav-next` 与 HTML 的
   `.viewer-chrome` / `.nav-btn` / `.prev` / `.next` 命名分叉 —— 已统一为 HTML 命名。
   若漏改，左右导航按钮会同时堆到左上角（定位规则失效）。
3. 空状态 HTML 用 `.hint-list`，CSS 只有 `.shortcuts` —— 已改 HTML 为 `.shortcuts`。
4. `.viewer-stage` 铺满全屏会吃掉背景点击，导致「点图片外关闭」永不触发
   —— 已加 `pointer-events: none`，`.slide` 用 `auto` 恢复。
5. `#cache-text` 原本没有任何数据源 —— 已在 `main.js` 接上 `cache_stats` 命令。
6. 关闭动画期间手势未冻结会打断 FLIP —— `close()` 开头置 `g.enabled = false`。

- 前端 `main.js` 末尾调 `api.showWindow()`。

### 关键 bug：选择了图片后界面无反应（已修）
**症状**：弹窗能出、选完图片后界面无反应，右上角显示「没有找到支持的图片」。

**排查路径（关键经验）**：先排除后端——用 `open_paths` 直接扫 `/tmp/picshow-test`
（3 张真图），确认 `expand` / `register` / `emit` 全通；再确认 TCC 不背锅
（`~/Desktop` expand=5、`~/Pictures` expand=352，只有 `Photos Library.photoslibrary`
因系统保护被拒，属正常）；最后用「事件往返探针」定位：
后端 `emit` 一个已知 payload → 前端记录收到的形状 → 发现收到的是
`{event, payload:{...}}` 整个包装对象。

**根因**：手写的 `tauri.js listen()` 里多包了一层。Tauri 桥接脚本
（`tauri-2.x/src/event/mod.rs` 的 `emit_js_script`）给回调传的已经是
完整事件对象 `{event, payload, id}`，`listen()` 又把它裹成
`{event, payload: eventData, id}` 传给 `api.js` 的
`(event) => handler(event.payload)` —— 于是 handler 拿到的是包装对象本身，
`payload.items` 恒为 `undefined` → 列表恒空 → 「没有找到支持的图片」。

**修复**：`listen()` 回调改为 `handler({ event, payload: eventData?.payload, id })`。

**教训**：手写 IPC 封装时，事件回调的参数形状必须实证（往返探针），
不能靠猜。这条已写进 README FAQ。

**附带教训——清理临时诊断代码不要用「切片截断」**：
曾用 `s.index('TEMP DIAG')` 到文件尾的方式清理 `api.js`，误删了
`onItems` 和 `preload` 两个导出。应使用精确的 Edit 操作，删完跑
`node /tmp/picshow_check.mjs` 交叉校验导出完整性。

### 关键 bug：手势与快捷键全部失效（已修）
**症状**：打开文件夹后图片能显示，但全屏查看器里拖拽、滚轮、双击、方向键全无反应。

**根因**：`ui/js/viewer.js` 调用了 `this.bumpControls()` 共 5 次（`open()` 末尾、
`go()` 中、`onTap`、`onUserActivity` 回调），但**这个方法从未定义**。

致命之处在于调用位置（最容易被忽略的一环）：
```js
onPointerDown(event) {
  if (!this.enabled) return;
  this.o.onUserActivity?.();   // → 就是 bumpControls，这里先抛异常
  this.pointers.set(...);      // → 永远执行不到，指针没被登记
}
```
`onPointerMove` 开头 `if (!this.pointers.has(id)) return;` —— 于是**所有手势全死**。
键盘侧：首次方向键能让 `go()` 走到 `bumpControls()` 抛错，导致
`previous.remove()` 与 `this.switching = false` 都不执行，切换**永久卡死**。

**修复**：补上 `bumpControls()`（清旧计时器 → 移除 `is-idle` → 重新定时 `IDLE_MS`
后加回 `is-idle`，并校验仍处于打开态）。

**防复发**：新增 `tools/check_methods.mjs`，静态扫描 `ui/js/*.js`，
核对 (1) 所有 `this.x()` 调用都有对应定义；(2) 所有具名导入的符号
确实被目标模块导出。已接进 `npm run check`（`cargo check` + 几何测试 + 本检查）。

> 为什么必须靠工具拦：前端是零打包器原生 ESM，打包期不会报错，
> 「方法未定义」只会在运行到那一行时才炸，表现为「按钮没反应」这类
> 无因果可循的静默故障。这已经是本项目第二次栽在同类问题上
> （前一次是 `api.js` 导出被误删）。

教训 —— **本项目应尽早建 git 仓库**，否则「回退到上一版本」只能靠记忆精确还原。

若日后重做，两个关键坑（当初踩过）：
1. 横滑**不能走 `settle()`**：`scale <= 1` 时 `panBounds` 的 maxX 为 0，
   `settle()` 会把已阻尼过的位移再压一次（二次阻尼），手感发死。
2. **wheel 与 pointer 的横向符号相反**：触控板两指向左滑 → `deltaX > 0`；
   触屏两指向左滑 → 中点 `mid.x` 减小。必须统一符号后再累积。
3. 触控板两指横滑在 WKWebView 里是**一串带 deltaX 的 wheel 事件**（非 pointer），
   需另用「累积 + 静止判定」模拟按下-移动-松手。

**回退时保留了两处独立 bug 修复**（与横滑无关，撤销会重新引入问题）：
- `gestures.js springBack()`：`scale < 1` 时回弹到 1。捏合缩小到 0.5 松手后
  原本会一直停在 0.5，违反「越界自动回弹」。
- `viewer.js syncOrigin(index)`：切换图片后把 `originEl` 挪到新索引对应的格子。
  否则关闭动画会飞回**旧图**位置，且旧缩略图一直隐形。

### 关键 bug：切换上一张/下一张「闪一下」（已修，2026-10-26）
两个独立成因，都要盯住，改 CSS/转场时极易踩回去：

1. **主因 —— `.viewer-stage` 被 grid 排成了两行。**
   stage 是 `display:grid; place-items:center`，而 `.slide` 没有指定行列 →
   转场时同时挂着的新旧两张 slide 被放进**两个隐式行**。新图先出现在错位的一行，
   等 `previous.remove()` 后只剩一行，又瞬间跳回中间 → 肉眼就是「闪一下」。
   探针实测（1440x900 无头，视口 1432x816）：修前 a 在 (316,200)、b 在 (416,0)（分属两行）；
   修后 a=(316,158)、b=(416,58)，**中心点都是 (716,408)**，完全重合。
   修法：stage 用 `grid-template: 1fr / 1fr`（不要 `grid-template-areas` + auto 行——
   auto 行会被最高的一张撑高，矮的那张就被顶偏），slide 用 `grid-area: 1 / 1`。

2. **次因 —— 对称交叉淡入淡出在黑底上掉亮度。**
   旧图 1→0、新图 0→1，中间帧合成亮度 ≈0.75，肉眼是「变暗再变亮」。
   修法：**错峰**。新图前 55% 淡到 1 并保持，旧图从 55% 才开始淡出；
   任意时刻都有一张不透明 → 合成亮度恒为 1。位移与透明度拆成两条 `animate()`
   （位移要 EASE 缓动、透明度要 linear 且带 offset），同一元素上不同属性的
   动画互不冲突。keyframe 用显式对象数组 `[{opacity:1,offset:0},...]`，
   不用 `{opacity:[..], offset:[..]}` 简写，兼容性更稳。

配套改动：
- 切图时**立刻** `startFullLoad()`，不等转场结束。转场只动 transform/opacity，
  跑在合成器线程，解码抢不走帧；换来的是转场一结束画面就是清晰的，
  不会「先糊后清」再跳一次。
- 转场期间 `g.enabled = false`，结束后恢复，避免中途拖拽与动画抢 transform。
- 放大状态下切图：旧图不位移、留在原地淡出（否则「先缩回再滑走」很突兀）。
- `previous.style.opacity = '0'` 预写终态（配合 `fill:'none'`），防止收尾闪回。

### 画廊模式改造（2026-10-26）：轨道 + 三槽 + 胶片条
需求：多图画廊、缩略图列表、上一张/下一张（键盘 + **移动端滑动**）、按缩略图跳转、
全屏显示索引/总数、缩放关闭、响应式、懒加载/占位/失败处理。

**核心决策：全屏从「单张 slide + 切换动画」改成「横向 track + 三个复用槽位」。**
理由：单 slide 方案只能等松手再播动画，手指跟不上画面（正是上次「双指横滑效果不太好」
的死因）；且每次切换都新建/销毁节点，低分辨率底图重新解码，中途必闪。

```
┌──────┬──────┬──────┐
│ prev │  cur │ next │   track.translateX = -cur × 视口宽
└──────┴──────┴──────┘
```
- **轮转 rebalance()**：切完把 DOM 顺序转一格（`appendChild`/`insertBefore`），
  slotIndex 回 1，基准偏移同步改回 -1屏。两者同一帧生效 → 视觉位置不动，
  只有被挪到视口外的那个槽需要换内容 → 不闪。
  - cur=2 → `appendChild(a)`，顺序变 [b,c,a]，填 a = index+1
  - cur=0 → `insertBefore(c, a)`，顺序变 [c,a,b]，填 c = index-1
- **三种变换分写两个元素**（千万别合并）：track = 横向槽位偏移；当前 slide =
  缩放/平移/下拉关闭/FLIP。FLIP 因此完全不用改（slide 居中于 track，等价）。
- 事件挂在 **track** 上（铺满视口）→ 「点图片外关闭」改为按坐标判断
  `isInsideImage(x,y)`，不再靠 backdrop 接点击。
- 放大态切图前要 `g.reset(false)`，否则旧图会以放大姿态留在邻槽。

**踩到的坑（改动这些文件时务必回看）：**
1. `fill()` 里必须先 `root.hidden = false` 再填充 —— hidden 时 stage 尺寸为 0，
   fitBox 会算出 0×0（探针里 stageW 也要在 open 之后量）。
2. **速度阈值会被单帧跳变骗到**：一帧里丢出 40px 的 pointermove，Δt≈0 → 速度虚高
   → 手指几乎没动就翻页。修法：`dt` 下限 4ms + 只靠速度翻页时要求位移 > 28px。
3. `touch-action` 与祖先**求交集**：`none` 挂在 `.viewer` 上会把胶片条的 `pan-x`
   一起吃掉，触屏划不动缩略图。现在 `none` 只挂在 `.viewer-track`。
4. 手写 `img.src = ''` / removeAttribute 也会触发 error 事件 → 用 `img.__want`
   记录「期望的 src」，只有 `getAttribute('src') === __want` 才算真失败。
5. 胶片条缩略图必须用与网格**同一个** `THUMB_SIZE`，否则跳转时底图不命中缓存会先白。

**新增文件**：`ui/js/strip.js`（窗口化渲染 ±40 张，DOM 恒定）、`ui/probe.html`、
`tools/probe_gallery.mjs`。`check_methods.mjs` 增加了「构造器里 `this.x =` 赋值」
也算已定义，否则 `this.onJump?.()` 会被误报。

## 窗口尺寸变化自适应（2026-10-26 续）

**问题**：最大化 / 还原 / 拖拽改窗口后，缩略图网格不重排（错乱、空白、溢出），
预览区图片不重新适配（不缩放、越界、大量留白）。

**根因（两处，都是「只算不写」）**
1. `grid.js` `update()` 只对**未挂载**的索引调 `mount()`，而几何是在 `mount()` 里写的。
   重排后 `rows`/`rowOf` 已是新值，但视口里那一屏 DOM 仍留着旧 `width/height/transform`，
   要等滚出去再从池子复用回来才更新 —— 这就是「错乱 + 溢出」的直接来源。
2. `viewer.js` `onResize()` 挂在 `window.resize` 上，只改 `--w/--h`，且
   `g.commit({scale:1,tx:0,ty:0})` 把用户缩放一并重置。

**改法**
- `grid.js`：抽出 `place()/refresh()/cellOf()`；`update()` 对已挂载项一律 `refresh()`
  （只写几何，不重请求缩略图 → 拖动窗口不闪）。`onResize()` 区分「宽度变（重排 O(n)）」
  与「仅高度变（只 update）」；0 尺寸直接跳过；`relayout({anchor})` 用
  `topIndex()` 记住视口顶部那一项，重排后算回 `scrollTop` 保持视觉位置。
- `viewer.js`：改用 `ResizeObserver` 观察 `.viewer-stage`（覆盖断点/DPI 变化），
  `window.resize` 兜底；`onResize()` 三件事：重算三槽 `--w/--h`、重算
  `trackOffset=-slotIndex*slotWidth()`（先 cancel 进行中的 `trackAnim`）、
  `g.refit()`。
- `gestures.js` 新增 `refit({base,view,maxScale})`：保留 `scale` 只夹
  `tx/ty` 到新 `panBounds`，并更新 `o.maxScale`。**不要用 `reset()`**，会丢倍率。
- `strip.js`：`onResize()` 原来只在跨断点时才动，现在任何宽度变化都
  `scrollToCurrent(true)` 重新居中。
- 三个组件的 rAF 合并统一改成「**先 cancelAnimationFrame 再 requestAnimationFrame**」。
  原先「`if (this._raf) return`」的写法，一旦某帧 rAF 被丢掉（隐藏页/元素移除），
  句柄永远挂着，之后的 resize 就再也不响应了 —— 这是实测踩到的真 bug。
- `nudgeAtEdge()` 的回弹第二段加了 `trackOffset !== to` 守卫，防止回弹途中改尺寸后被拉回旧偏移。

**探针**（`ui/probe.html`，38 → 57 项）
- 新增 8.1 网格重排（几何一致性 `geomProblem`、DOM 节点不重建、滚动锚定、仅高度变不重排、
  0 尺寸跳过）、8.2 预览区（`--w/--h`、等比 `w/h ratio`、居中、轨道偏移、RO 接线）、
  8.3 保留缩放并夹平移、8.4 胶片条重新居中、还原尺寸后再次正确。
- **无头环境坑（重要）**：页面加载完之后 headless 基本不再产生渲染帧，
  `requestAnimationFrame` 不回调 → `ResizeObserver` 回调也不投递。
  加 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding
  --disable-background-timer-throttling` 会好一些但仍不稳定。
  最终做法：探针断言三个组件都挂了 RO，然后把 `requestAnimationFrame` 临时换成
  **同步执行**再手动调 `onResize()`（与 RO 回调同一入口），确定性验证重排逻辑。
  另外 `--virtual-time-budget` 要 ≥30s（实测每帧虚拟时间约 1000ms）。
- 负向验证：把 `update()` 里的 `refresh` 去掉后，探针报
  `#0 w 438≠243` 与 `锚点 -90 → 128` —— 说明断言确实能抓住原 bug。

## 空闲自动隐藏导致卡顿 / 鼠标失灵（2026-10-26 续）

**现象**：底部画廊与上一张/下一张按钮自动隐藏后，界面卡顿、鼠标像动不了。

**根因一（鼠标"失灵"的真凶）：空闲计时器不响应 pointermove**
`onUserActivity` 只挂在 `pointerdown / wheel / dblclick` 上，`pointermove` 不唤醒。
而 `.viewer.is-idle .slide { cursor: none }` 又让指针彻底不可见 —— 用户移动鼠标时
屏幕上**什么都不会发生**，主观就是「鼠标动不了、界面卡死」，必须点一下才恢复。
→ `gestures.js` 新增 `noteMotion()`，在 `onPointerMove` 最开头调用（必须早于
`pointers.has()` 的 early return），节流 `MOTION_WAKE_MS = 120`（~8 次/秒）。

**根因二（真正掉帧来源）：只降 opacity 不会让元素退出合成树**
胶片条窗口半径 40 → 常驻 81 个 DOM 节点，待加载项的 shimmer 动画用
`background-position`，**该属性无法交给合成器**，每帧都要主线程重新光栅化。
只把 opacity 降到 0 并不会中止它们 →「界面看着空了，主线程还在刷渐变」。
→ `app.css` 的 idle 规则同时收 `visibility: hidden`（延迟 0.3s 到淡出结束），
并加 `.viewer.is-idle .strip-item.is-pending::after { animation-play-state: paused }`。
`.nav-btn` 上的 `backdrop-filter: blur(10px)` 同理，隐藏后不再参与合成。

**根因三：pointer-events:none 打断指针序列 → 状态残留**
空闲时给 `.nav-btn` 加 `pointer-events: none`，若此刻它正持有指针捕获，
浏览器会隐式释放捕获并改派 `pointercancel`，`pointerup` 永远收不到。
`Gestures.pointers` 里残留的 pointerId 让之后**每一次** pointermove 都通过
`pointers.has(id)` 走进拖拽分支并 `preventDefault()` → 画面一直"粘"在鼠标上；
且 `dragging` 恒为 true 会让 `Viewer.onResize()` 永远跳过手势收敛。
→ `bumpControls()` 到期时先查 `busy`（`pointers.size > 0`），按着就隔
`IDLE_RETRY_MS = 300` 重试，**绝不**在交互中途抽掉 pointer-events（不能
直接 return 放弃，否则这次交互结束后控件就再也不自动隐藏了）。
→ `gestures.js` 新增 `abort()` + `resetPointerState()`；`window.blur` 兜底；
`detach()` 里也清干净。判断"正在交互"统一用 `busy` 而不是 `dragging`。

**探针**：38 → 57 → 73 项（新增第 9 节：空闲 vs 指针事件）。
负向验证三处全命中，尤其去掉 blur 兜底时报 `失焦后移动不再被当作拖拽 :: -120`，
直接证实了 phantom drag（鼠标松开画面仍跟着走）。

**环境坑**：headless Edge 在本机现在起不来自己的沙箱
（`Failed to initialize sandbox` → GPU/network service 崩退出，exit=133），
探针脚本已加 `--no-sandbox`（仅用于加载 127.0.0.1 上的自有页面）。
另：CSS transition 的计算值同样依赖渲染帧，**不要**在探针里断言
（比如隐藏后的 `visibility`），改断言样式表规则本身。

## 从文件管理器打开（右键 → 打开方式 → PicShow）（2026-10-26 续）

**后端**
- `scanner.rs` 新增 `scan_siblings(target) -> (Vec<PathBuf>, Option<usize>)`：
  目标文件所在目录**非递归**扫描，按**文件名**自然排序（不是全路径，虽然同目录等价，
  但语义要清晰），返回目标下标。同目录文件名唯一 → 按 `file_name()` 定位即可，
  不必逐个 `canonicalize()`（每张图一次系统调用）。大小写不一致时回落
  `eq_ignore_ascii_case`。单测 4 项（自然排序 / 不递归 / 只有一张 / 不支持格式不入列）。
- `commands.rs`：`open_file_context` / `take_launch_target` / `exit_app` / `log_error`；
  `deliver_launch()` 是唯一入口 —— **既发事件也存 pending**。
- `state.rs`：`launch: Option<LaunchPayload>`（取完即清）、`ready: AtomicBool`、
  `launched: AtomicBool` + `launch_title`。
- `lib.rs`：`build()` + `app.run(callback)` 两条通道：
  `RunEvent::Opened`（macOS 走 Apple Event，argv 里没有文件）与 `argv_targets()`
  （Windows 关联打开 / Linux .desktop %F / 命令行自测）。

**冷启动 vs 已运行（关键设计）**
后端在 webview 执行第一行 JS **之前**就把 `picshow://open-file` 事件发出去了，
那时没有监听者 → 事件丢进黑洞。所以必须两条腿：
- 冷启动：前端 ready 后 `take_launch_target()` 主动取（`launchByEvent` 标志防重复打开）；
- 已运行：走事件，直接换集合并跳转（先临时摘掉 exitOnClose 再 close，否则会中途退出）。

**平台集成**
`tauri.conf.json` → `bundle.fileAssociations`（`ext / name / role:Viewer / rank:Default /
mimeType / contentTypes`）会自动生成 macOS `Info.plist` 的 `CFBundleDocumentTypes`
+ `LSItemContentTypes`、Windows 注册表、Linux `.desktop` 的 `MimeType`。
**不要**给 mime 写 `image/*`：tauri-utils 的 `mime_type_to_uti` 对未知 `image/xxx`
会回落到 `public.image`，等于声明「能开所有图片」（包括解不开的 HEIC）。
所以 ico 只写 `contentTypes: ["com.microsoft.ico"]`，不写 mimeType。

**踩到的坑（都实测过）**
1. `api.setWindowTitle` 根本不存在 —— `setWindowTitle` 定义在 `tauri.js`，
   `api.js` 只 re-export 了 `isTauri/showWindow`。调用方是 `api.xxx` 命名空间，
   这类漏导出**静态检查查不出来**（`import * as api` 不是具名导入），运行时才炸。
   → api.js 现在 re-export 它；但窗口标题最终改到 Rust 侧 `set_title`（更可靠）。
2. **对隐藏窗口 `maximize()` 不可靠**：macOS 会在真正 show 时把尺寸改回去，
   实测时有时无。→ `window_ready` 里先 `show()` 再 `maximize()`。
3. **debug 二进制加载的是 `devUrl`**（`http://localhost:1420`），不是 `frontendDist`。
   直接跑 `target/debug/picshow` 而不起 `node tools/serve.js` → 白屏、JS 完全不执行，
   只有 lib.rs 里 3s 兜底 show 会亮一个黑窗口。排查时先确认 dev server 在跑。
4. webview 的 `console` 不进终端。加了 `PICSHOW_DEBUG=1` + `log_error` 命令，
   main.js 里兜住 `error` / `unhandledrejection` / `boot().catch` 上报。
   没有它，前端异常只能靠猜（本项目已经第三次栽在这上面）。
5. `go()` 在循环分支里**必须 return jumpTo 的 promise**，否则调用方无法 await，
   连续两次 `go()` 会因 `switching` 仍为 true 而第二次被吞掉（探针抓到了）。

**前端**
- `main.js`：`enterImmersive()`（is-immersive class → grid/viewer.setItems → setExitOnClose(true)
  → open）；`boot()` 顺序：take → 加 is-immersive → showWindow（Rust 侧 maximize+title）
  → **等 2 帧** → enterImmersive（等帧是为了让尺寸落定，避免按旧尺寸适配完又弹一下）。
- `viewer.js`：`setExitOnClose()` / `setLoop()` / `updateNavState()`；
  `finishClose()` 里 `if (this.exitOnClose) this.onExit()`；
  `go()` 到头时：不循环 → nudge，循环 → `return this.jumpTo(wrap)`。
- CSS：`body.is-immersive` 隐藏 topbar/grid/empty（用 `display:none`，不是 opacity，
  否则网格仍在参与布局、RO 白跑一遍）；`.nav-btn:disabled`；`.viewer.no-strip .nav-btn{display:none}`。

**验证**：`npm run rust:test` 4 项；`npm run probe` 90×2（新增第 11 节 16 项，
含退出回调、单图、首末禁用、循环、沉浸式 CSS）；负向验证两处均命中。
真机截图确认：标题 `IMG_10.png — PicShow`、最大化、`IMG_10.png 3 / 3`、

## 「打开方式」直达全屏 + 从小到大开场动画

**需求**：不再先创建/显示主界面（含一闪而过）；直接沉浸式全屏 + 从资源管理器那一格
放大；拿不到来源 → 中心 0.8 倍兜底；只改这一条入口。

**入口分流**：`main.js boot()` 里 `pending?.items?.length` → `bootLaunch()` 并
**return**（`showWindow()` 那条常规路径压根轮不到）。删掉 return 的那次探针精确报
「启动分支走上之后直接 return」失败 —— 这条断言是防主界面复现的关键。

**顺序**：`prepare_launch_window` 在窗口**还藏着**时 set_decorations(false) +
set_position/set_size(目标屏可用区) → show → maximize → set_title → set_ready。
Rust 里绝不能为拿显示器信息去查 `current_monitor()`（阻塞 getter，可能自锁），
所以矩形由前端 `window.screen.avail*` 算好传进来。

**来源矩形**：没有桌面平台会告诉你「点了哪一格」。近似方案 = 后端在
`deliver_launch()` 里记录光标位置（物理像素，桌面坐标系）+ 前端换算成 96px 矩形。
两个实测出来的坑：
- `AppHandle::cursor_position()` 是**阻塞等回执**的 IPC（RuntimeHandle 路径）。
  必须在**后台线程**里问（`capture_launch_origin` 用 `std::thread::spawn`），
  命令可能跑在主线程 → 直接自锁。为此连 `scale_factor()` 都不查，物理→CSS 交给前端
  devicePixelRatio。
- `window.screenX/screenY` 在无边框最大化窗口上是离谱的过期值（实测 1080）。
  改用 `screen.availLeft/availTop`：启动路径一定最大化到可用区，两者相等。

**顺序坑 2**：maximize 的结果比 IPC 回执晚 1~2 帧，而 FLIP 起点按**当前**可视区算。
早算会让动画从错方向长出来 —— 所以动画前 `waitFor(尺寸==目标, 8 帧)`。实测这之前
innerWidth 还是 1200，等完就是 1920 了。
**顺序坑 3**：`.viewer` 在 open 之前是 `hidden`，`stage.clientWidth` 恒为 0，
不能用它当等待条件（第一版就踩了，白等 8 帧）。

**动画**：`viewer.js` 新增 `openLaunch()` / `zoomStart()`；`open(index, el, opts)`
加三参（rect 优先于缩略图元素，元素优先于 rect 参数，都没有 → centerScale → null）。
起点用现成的 `mapBoxToRect()`，再叠加 `opacity [0,1]`；时长 `OPEN_MS=340`、
缓动沿用 `OPEN_EASE`（已导出给探针比对）。**不阻塞首帧**：几何来自 items 的宽高
元数据，`fill()` 同步；来源坐标那一问与「点亮窗口」并行发出。

**验证**：probe 153×2（第 14 节：坐标换算/三种 null 情况/0.8 兜底/起点优先级/
首帧/终帧/透明度/时缓动/不等图片/窗口原点取自可用区/等尺寸）。负向验证 4 条：
删 return、兜底改 1.0、去掉 fadeIn、以及 waitFor 条件写错都精确报 FAIL。
真机：来源坐标 (1222.8,1175.4) 物理 → rect(563.4,514.7,96,96)，与手算一致；
把 OPEN_MS 临时改成 5000 并强制起点在左上角，截图确认早期帧确实从左上角长出。
