## 落位速度连续：消除「接近居中硬停 → 缓慢居中」（仅改 wheel 补完落位）

**症状**：macOS 触控板双指横滑切图，目标图进入屏幕、接近中间时先硬停一下，
之后才以明显更慢的速度移到居中。用户要求只优化「停顿到缓慢居中」这一段，
wheel 触发判定、方向映射、其他交互、既有代码结构都不动。

**先用数值模型把速度量成事实，再读代码**（沿用本项目排查观感问题的纪律）。
1440px 视口复刻 `wheelFollowOffset` + `EASE` + 固定 180ms：

| 场景 | 跟手末速 | 结算静默 | 落位首帧 | 落位 85% 时刻 |
| --- | --- | --- | --- | --- |
| 典型轻甩（285px，剩 1156px） | 0.063 px/ms | 65ms 内速度 0 | 28.6 px/ms（×458） | 0.08 px/ms（≈0.3% 初速） |
| 长甩（压缩到剩 61px） | ≈0（橡皮筋渐近把显示速度压没） | 同上 | 1.5 px/ms | 0.004 px/ms |

`EASE = cubic-bezier(0.22,1,0.36,1)` 前 13% 时间走完约半程、末 35% 时间只挪
约 1%，最后 1% 行程占 35% 时长 —— **断层在结算落位，不在跟手或贴边**。
固定 180ms 还让只剩几十 px 的余数也慢慢挪满一档动画。

**实现**（产品代码只动 `ui/js/gestures.js` 与 `ui/js/viewer.js`）：

- `gestures.js::settleWheelSwipe()` 在 `clearWheelProgress()` 清零之前算
  `velocity = max(|s.vx|, s.peakV * 0.4)`，同时传给
  `onWheelSettle(false/true, velocity)` 与 `onWheelSwipe(direction, { fromSwipe, velocity })`。
  峰值的一部分兜住「刚进视口时」的节奏，避免惯性尾巴末尾的微弱样本把落位拖回慢速。
- `viewer.js` 新增 `WHEEL_LAND_MIN_MS = 24` / `MIN_V = 1.4` / `MAX_V = 4` /
  `X1 = 1/3` / `X2 = 2/3`；`WHEEL_LAND_MS = 180` 从「固定时长」变成**上限**。
  新增纯函数 `wheelLandTiming(dist, velocity)` 与 `wheelLandDistance()`：
  `T = clamp(2·dist/v0, 24, 180)`；缓动 `cubic-bezier(x1, y1, x2, 1)`，
  `y1 = x1·vStart·T/dist` ⟹ 起点速度 = vStart、终点速度 = 0；
  `vStart = min(v0, dist/(T·x1))` 保证 `y1 ≤ 1` 不过冲，并作为实际起点速度返回。
- `go()`：`fromWheel` 用 `landing.duration` / `landing.easing`，其余入口仍
  `SWITCH_MS` + `EASE`；`onWheelSwipe` 接线没改，`velocity` 经既有 `...opts` 透传。
- `releaseWheelSeam(rebound, velocity)`：补完时调同一个 `wheelLandTiming()`，
  贴边量 CSS transition 与轨道 WAAPI 逐字节同源；取消回弹仍是 200ms / EASE_SOFT。

**关键踩坑**：`MIN_MS` 最初取 60，桌面与窄屏探针立刻报「85% 时刻速度只剩
2.5% 初速 / 最后 1% 行程占 21% 时长」—— 短余数被顶到 60ms，所需初速斜率
超过匀减速两倍，曲线退化成「猛起 + 近零速度慢尾」，恰好复刻旧毛病。
**下限必须足够短（24ms），并让 `vStart` 按不过冲上限自洽**；否则「修好速度
交接」反而做出新的慢尾。窄屏另有 `m = 0`（图片铺满宽度）时没有贴边量可归零，
`releaseWheelSeam` 不写 transition 属正常，探针断言要允许这条退化路径。

修复后实测：长甩剩 61px → T≈41ms、从交接初速 3 px/ms 匀减速到 0、
85% 时刻 15% 初速、最后 1% 行程占 10% 时长（旧 EASE 分别 0.3% / 35%）；
轻甩起点速度 1.4~2 px/ms（旧 28.6），全程无快起、无慢尾。
