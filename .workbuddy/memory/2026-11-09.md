## WKWebView 相位能力实测（新增 `tools/appkit_wheel_phase.swift`，仅探针）

**结论：Web 层确实拿不到手势相位；原生侧拿得到，且两路同源可对齐。**

- `--capabilities`：本机 WKWebView（WebKit 605.1.15）的 `WheelEvent.prototype`
  只有 12 个属性，`phase` / `momentumPhase` / `momentum` /
  `hasPreciseScrollingDeltas` / `isDirectionInvertedFromDevice` **全不存在**；
  唯一带 webkit 前缀的 `webkitDirectionInvertedFromDevice` 只是 invert 布尔，
  不是相位。实例自有属性仅 `isTrusted`。全局 `GestureEvent` 是 Safari 触摸
  捏合/旋转手势，与触控板滚轮相位无关，别误用。
- `--synth`（`NSApp.sendEvent`）：本地监视器 6/6 读到非零 phase
  （began / changed / changed / ended）与 momentum began；Web 侧 0 个 wheel ——
  该注入路径不经过 WKWebView 的 wheel 翻译，属预期。
- `--synth-post`（`CGEvent.post` session tap）：**两路各 4 个事件一一对应**，
  native `scrollingDeltaX` 18/27/9/6 ↔ Web `deltaX` -18/-27/-9/-6
  （**符号相反**，实现监视器时别把原生数值直接当 Web 增量用）；两路时间戳
  相差约 1ms，证明「Rust 侧 `NSEvent` 本地监视器 → Tauri event → viewer 前端」
  这条补强路线在工程上可行。CG 滚轮相位字段是顺序枚举 1/2/4/8，AppKit 读出的是
  **位标志** `NSEventPhase`（1/2/4/8/16/32），即写 n 读 `1<<(n-1)`；合成 momentum
  字段写 4 实测读 none，只有写 1 稳定得到 began。
- `--seconds 3` 空跑正常退出（0 事件）；真机双指横滑与惯性手感仍需人工验收，
  不据此假报成功。

探针不参与构建、不碰产品代码，跑法见文件头。本次未实现原生监视器。

## 真机验证（`--seconds 12 --out /tmp/wheel_live.jsonl`，同日）

**先修探针 bug**：`NSEventPhase` 是位标志（1 began / 2 stationary / 4 changed /
8 ended / 16 cancelled / 32 mayBegin，见 `NSEvent.h`）；先前按 CG 顺序枚举标注，
把 changed 读成 ended、ended 读成 cancelled。已修 `phaseNames`，`--synth` 复跑
标签为 began/changed/changed/ended。JSONL 保留 `phaseRaw`，真机数据无需重跑。

**4 次双指横滑，213 个原生事件 / 205 个 Web wheel**：
- Web：`WheelEvent.prototype` 12 项，phase / momentumPhase / momentum /
  hasPreciseScrollingDeltas 全无；205/205 `isTrusted`，自有属性只有 `isTrusted`。
- 原生：`precise` / `targetIsProbe` / `isKey` / `subtype=1` 全 213/213；
  phase began 4 / changed 31 / ended 4；momentum began 4 / changed 166 / ended 4。
  主手指段 117~150ms，惯性段 266~1134ms（一次长甩累计 ΔX 1585px）。
- 两路配对 205/213，native→web 延迟中位 0.13ms / max 8.4ms；非零对里
  `scrollingDeltaX` 与 Web `deltaX` 符号相反且绝对值相等（204/204）。8 个未配对
  中 7 个是 ΔX=0 的 ended/began 边界事件 —— **WKWebView 不把零 ΔX 边界事件转成
  wheel**，Web 侧永远看不到明确结束点（另 1 个是配对游标误差）。
- **65ms 静默的实测误差**：段内 web 间隔 max 33~37ms、无 >65ms 空隙 → 不会提前
  结算 ✓；但 G3→G4 两次连滑的静默只有 58ms（原生段间隔 50ms）< 65ms，会被
  `sincePrev >= 65` 判成同一段，`settled` 闸门把第 4 次滑动当惯性尾巴吞掉 →
  **少切一张** ✗，4 次只结算 3 次。段间另两次静默 236ms / 118ms 均正确分开。
- 调阈值可救但窗口极窄：段内 max 37ms、段间 min 58ms，只有 37~58ms 区间可用
  （例如 45ms）；样本仅 4 次，帧率 / 机器一变就翻车，治标不治本。根治要用原生
  `momentumPhase.ended` 作结束信号，65ms 静默保留作兜底。
- 另注：G4 惯性 ended 前仍有 20~22px 的 ΔX（用户中途起手打断惯性），说明
  「手势结束 ≠ 速度归零」，落位速度交接要按真实结束点算，不能假设已停稳。

**结论**：Rust 侧 `NSEvent` 本地监视器路线不仅工程可行，其必要性已被真机数据
证实；本次仍未实现、未改任何产品代码。真机惯性手感与逐帧观感仍需人工验收。

### 慢滑复位（wheel 取消回弹）优化：只改回弹曲线，快滑路径零改动

- 用户反馈：慢速横滑后图片复位生硬；快滑复位迅速且可接受，要求保持不变。
- **定位**：慢滑未达标只走 `settleWheelSwipe` 的**取消回弹**分支，此前固定
  `200ms + EASE_SOFT`（cubic-bezier(0.33,1,0.68,1) 起点速度≈3×平均），
  而慢滑手指末速仅 0.1~0.3 px/ms → 松手瞬间突然加速 = 生硬。快滑达标走
  补完 `wheelLandTiming()`（T=clamp(2d/v0,24,180)、起点速度=vStart、终点 0），
  本来就快且连续，**一行未动**；边界段 swipeX≡0 也走回弹。
- 修复（范围只在 wheel 回弹与贴边归零）：
  1. `viewer.js` 新增 `wheelReboundTiming(dist, velocity)`：时长仍
     `WHEEL_SEAM_REBOUND_MS=200`；`v0=clamp(|v|, 0.08, 4)`
     （`WHEEL_REBOUND_MIN_V=0.08`，**不能**套落位的 1.4，否则 y1 顶回 1）；
     `vStart=min(v0, d/(T·x1))`、`y1=x1·vStart·T/d`；`y1>=0.999`
     直接返回原 `WHEEL_SEAM_SOFT_EASE` 字符串（高速/边界逐字不变）。
  2. `wheelReboundDistance()` 读 `|g.swipeX|`（最小 1）；边界段退化为 1 →
     y1 自动顶到 1，边界回弹保持原曲线。
  3. `releaseWheelSeam()` 回弹分支改用它并 **return timing**；
     `attachGestures` 的 `onWheelSettle` 箭头函数隐式把返回值交给
     `Gestures.reboundWheelSwipe(timing)`；后者容错取 duration/easing，
     无上层 timing（纯逻辑替身 / 非 viewer 调用）逐字退回 200ms/EASE_SOFT。
     轨道 WAAPI 与贴边 CSS transition 共用同一对象，天然同源。
- **未改**：结算时机（65ms / 24ms）、settled 闸门、方向/位移/速度判定、
  贴边公式、`wheelLandTiming` / `go()` 补完、边界弹性、连续滑动接管逻辑、
  窗口 / 相位 / Rust 全不动。
- 同步：`check_trackpad.mjs`（4 条旧断言改语义 + 2 条新断言）、
  `check_wheel_swipe.mjs`（harness 可注入 settleTiming、makeTrack 记录
  duration/easing、第 30 组 4 条）、`ui/probe.html`（`17.21a~e` 六条；
  `17.18` 的 releaseWheelSeam 包装必须 `return realRelease(...)`，否则探针里
  两条曲线不同源）、README 新增「慢滑复位」设计小节与回归清单。
- 验证：`npm run check` RC=0；`npm run probe` 双视口各 **282/282**（原 276+6）；
  `check_exit` 60/60。反向变异（把 releaseWheelSeam 回弹分支改回固定常量）：

  逐字节一致、全套复绿。**真机惯性手感仍待人工验收**（曲线可数值验证，

### 相位链路收敛成默认开启的产品能力（同日，用户问「两种启动为什么快滑流畅度不同」后决定）
