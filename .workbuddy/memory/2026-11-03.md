## 评估：交通灯标题栏能否与「选择图片 / 选择文件夹」按钮合并为同一栏

**结论：不可行 → 保持原结构，产品代码零改动。** 只在 README 顶栏那一节补了一段
边界说明（最小替代，纯文档）。

### 事实（读代码得到，不是猜）

- 交通灯是 **macOS 原生控件**，`macos.rs::apply_immersive_frame` 只是给每条窗口
  设 `Titled + FullSizeContentView + 透明标题栏 + 隐藏标题文字`，并用
  `.topbar { padding-left: calc(14px + var(--traffic-light-inset)) }` 给它让位。
  它不是 DOM 元素，无法并入某个 flex 行；「与交通灯同处一栏」在平台层面**只有
  `.topbar` 这一种形式，而且已经做到了**（同一条栏内已有打开图片 / 打开文件夹 /
  主题）。
- 「选择图片 / 选择文件夹」在 `index.html` 的 `.empty-actions` 里，属于 `.empty`
  空状态面板（图标 + h1 + 提示语 + 按钮 + 快捷键表），`inset: var(--topbar-h) 0 0 0`
  居中在**内容区**，只在没有图片时出现；顶栏是常驻的。它不是「另一条栏」。
- `main.js:303-306` 四个按钮全绑到同一个 `pick('files'|'folder')`；`applyHostMode`
  的禁用列表同时列了四个 id。两组入口功能/可用性天然一致。

### 为什么硬合并会违反用户列的约束

1. 与顶栏已有的「打开图片… / 打开文件夹…」重复 —— 五个按钮两个命令；
2. `.topbar` 是 `flex-wrap: nowrap`、固定 `--topbar-h` 的单行，main 窗口
   `minWidth: 460`（再减 78px 交通灯让位）已经要靠 ≤520px 断点收紧才放得下三个
   按钮；再加两个必然溢出，只能压缩/藏按钮 → 破坏「按钮可用性」；
3. 移走按钮后空状态「或者直接选择」失去所指，`.empty` 布局跟着变 → 破坏
   「整体布局稳定 / 内容区不受影响」；
4. `.grid` / `.empty` 的 `inset` 与 `body.is-immersive` 隐藏规则都按 `--topbar-h`
   钉死，改顶栏高度会连带错位。

## 修复：多桌面（Space）时「打开方式」退出预览回到触发打开的桌面

**根因不在全屏转场，在激活**：用户把访达放在第 2 个 Space，右键「打开方式」
→ PicShow 被 LaunchServices 唤起。系统切到「包含该应用窗口的桌面」，而冷启动
那条隐藏的 `main` 窗口被算在第一个 Space；全屏预览窗口销毁后 AppKit 回到
「进入全屏前所在的 Space」，于是把用户送回第一个桌面，访达窗口和焦点留在原处。

macOS **没有公开 API** 指定「回到第 N 个桌面」（`CGS*` 是私有）。唯一可靠做法是
**激活那个桌面上的应用**（`NSRunningApplication.activateWithOptions:`）——
WindowServer 会把桌面、key window、焦点一起交还。所以修复只有两半：

| 半边 | 位置 |
| --- | --- |
| 记录 | `lib.rs::run()` 第一行（`NSApplication` 初始化 / 应用被激活**之前**）读 `NSWorkspace.frontmostApplication`，`RunEvent::Opened` 开头再捕获一次；`macos.rs::capture_launch_source()` 记 pid + bundleId |
| 交还 | 沉浸式退出 `exit_app` / `ExitRequested` → `commands.rs::hand_back_launch_source()` → `macos.rs::restore_launch_source()` 按 pid 找回、核对 bundleId 后 `activateWithOptions` |

**改动面刻意收得很窄**：`hand_back_launch_source` 要求 `was_launched() &&
space_restore_armed()` 双条件，`space_restore_armed` 只有 macOS `RunEvent::Opened`
（访达打开方式的 Apple Event）会置起。命令行 `picshow <文件>` 不经过 Opened，
拖放 / 文件对话框 / 图片墙点开都走 `close_viewer → reveal_main_window()`，
一行都没碰；单桌面下等价于把焦点还给打开它的应用。交还是一次性的
（`SOURCE_HANDED_BACK` 闸门），`exit_app` 与 `ExitRequested` 叠加不会切两次；
`exit_app` 里先销毁全屏窗口 → 再交还 → 留 140ms 给异步激活落地 → 才 exit(0)。
来源应用找不到才回退访达（`find_finder`），连访达都找不到就什么都不做。
pid 复用靠 pid + bundleIdentifier 双标识防住（`find_by_identity` / `same_identity`）。

平台事实由 `tools/appkit_space_restore.swift` 测成：进程最早期 `frontmost` 读到
的是触发打开的外部应用（本次会话是 `com.apple.loginwindow`，非自己），`byPid`
命中，Finder 常驻；无 GUI 激活会话里 `activate()` 返回 false，探针如实打印不
假报成功。
