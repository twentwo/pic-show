## 本轮：目标图贴边跟随（wheel 起手第一帧就进视口）

用户报告「上次改动后目标图片出现仍不明显」：上一轮修的是**槽位永不空白**，
但槽里有像素 ≠ 图片贴着边缘。要求只动全屏预览上一张/下一张切换逻辑，不改
其他模块 / 样式 / 既有交互；wheel 一起手目标图就必须从对应侧边缘连续进入，
两张图同时可见、无空白/跳变/闪烁，方向与索引边界不变。

### 先量事实，别猜

在 `ui/probe.html` 里临时塞一段 DIAG 真 DOM 诊断，用无头浏览器逐帧量
「目标槽近边 vs 目标图近边」。基线数据（1440×900 桌面，stage 1432px 宽，
图片 1204px 宽，`swipeX = 12 / 30 / 54 / 84 / 120 / 162`）：

- 目标**槽**近边：`12 / 30 / 54 / 84 / 120 / 162`
- 目标**图**近边：`-102 / -84 / -60 / -30 / 6 / 48`
- 即固定差 `114px = (1432 - 1204) / 2`，`object-fit: contain` 的居中留白。

结论：**前 114px 的滑动里目标图一个像素都没进视口**，之后才慢慢露出。竖幅
照片这个差能到三四百 px。上一轮的原子换源 / 预热排序解决的是「槽空」，
没有解决「图片没贴边」—— 这正是「目标图片出现不明显」。

  `settleWheelSwipe()` 的补完 / 回弹两个分支真正动作前各触发一次。
- `viewer.js`：

    `translate3d(-dir · m · (1 - p))`，其余槽归零；`m` 只从缓存的
    `slot.__box.w` 算，热路径零布局读取。
  - 贴边前先校 `target.__index / __shown`，不对就 `fill()`；再用
    `bindSlotPixels()` 补装「预热晚于 fill」的已解码底图 + 原图。
  - `setSlotSeam()` / `clearSlotSeam()` / `paintSlotSeam()`：换源继承贴边量，
    换内容 / 关闭硬清空。
  - `releaseWheelSeam(rebound)`：CSS transition 归零，补完

### 环境坑（写下来免得再踩）

本机 Edge 152 headless 常在 `--dump-dom` 输出完整 DOM 之后**不退出**，
`npm run probe` 因此偶发 SIGTERM / 137 / alarm 142。用独立 user-data-dir
反而更糟（首启挂住）。可靠做法：`spawnSync(..., { timeout })` 拿 ETIMEDOUT
时照常解析已捕获的 stdout（`<pre id="out">` 是完整的），别把退出挂住
当成探针失败；临时脚本 `/tmp/picshow_probe_dump.mjs` 就是这么读 17.17 的。
这次没有改动 `tools/probe_gallery.mjs`（超出本轮范围）。

## 产品语义变更：wheel 横滑改回「一次完整滑动只切相邻一张」

用户给出明确契约：一次滑动 = 从手势开始到结束的一整段横向 wheel 流（含惯性
尾巴），每次最多一次切换且只到相邻一张；首张 / 末张继续往外滑不循环、不越界、
不空白，只让当前图回弹；方向映射、动画风格、索引规则与缩放 / 按钮 / 键盘 /
非全屏状态一行不改。**注意这与历史的 `locked` 版不是一回事**：老版把惯性尾巴
吞掉、画面不跟手，被判体验退化并回滚；这次保留连续模型的全部跟手 / 动画实现，
只把「索引变化」收成一次。

实现（仅 `ui/js/gestures.js` + `ui/js/viewer.js`）：

- `gestures.js`：删掉逐屏推进循环与 `WHEEL_ADVANCE_MAX`，`onWheelAdvance`
  只剩**带注释的默认回调**（作为不牵动 `advanceBy` 配套代码的保留接口，
  当前 wheel 流一行都不调用）；`t.x` 保留真实累计行程，
  新增 `wheelFollowOffset(x, limit)` 渐近压缩
  （前 `WHEEL_FOLLOW_LINEAR_RATIO` = 75% 仍 1:1，超出走 `rubberband`），
  `limit` 由 `onWheelCanStep` 决定：正常方向 = 视口宽，边界方向 =
  `WHEEL_OVERSCROLL_RUBBER + 1`。新增 `wheelSwipe.settled`：只在
  `settleWheelSwipe()` 补完 / 回弹两个真正落地的分支里置起，
  `handleWheelHorizontal()` 对同段后续事件只 `preventDefault`、不记账、
  不写轨道、不重排结算。静默 ≥ 65ms 时 `clearWheelProgress()` 连带复位
  `settled`（与结算共用一个刻度）。起手方向 `t.dir` 只记一次，中途掉头后
  `reversed → hit = far`，不靠峰值速度补一张。
- `viewer.js`：`attachGestures()` 不再注册 `onWheelAdvance`（`onSwipeIntent`
  仍在起手时预取目标那张），新增
  `onWheelCanStep(direction)` —— 只问 `index + direction ∈ [0, n)`，
  **不看 `this.loop`**；`onWheelSwipe` 仍只 `go(direction, { fromWheel: true })`。
  `advanceBy()` 保留为单步同步换页原语但当前 wheel 流不调用，注释改为
  「当前 wheel 流不调用它」。
- 边界空白：越界槽仍由 `fill()` 用当前图缩略图保底，`90px` 阻尼不会把空槽
  整屏拉进来；`loop` 开着时按钮 / 键盘仍可循环，wheel 绝不绕回另一头。

回归同步：`check_wheel_swipe.mjs` 全文重写为 26 组「一次一张」时序（3/4/21/22/
23/25/26 组分别钉流中零换页、行程与张数无关、只结算一次、首尾只反弹、

开启）不循环 / 不空白 / 只回弹；README「交互一览」+「一次手势最多换一张」+
「一次滑动只切一张」+ 三层回归段落同步。

验证：`npm run check` RC=0（0 个 ✗）、`test:exit` 60/60、`test:wheel` /
`test:trackpad` 全绿、`npm run probe` 桌面与窄屏各 258/258（新增
