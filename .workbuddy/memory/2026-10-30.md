# 2026-10-30

## 统一全屏预览入口（图片墙点击 ≡ 「打开方式」）

需求：图片墙点击图片时，要跟右键「打开方式」用同一种全屏预览（开场/遮罩/关闭动画
一致、交互一致、不保留两套实现）。

调研结论：**两条路本来就共用同一个 `Viewer` + 同一套 `Gestures`**，并不是两套组件。
真正的差异只有四处，其中三处是枚举出来的「调用约定」：

| | 图片墙点击 | 打开方式 |
| --- | --- | --- |
| 开场几何 | `open(index, cell)` | `open(index, null, {fromRect, centerScale})` |
| 开场渐变 | **没有**（少传 `fadeIn`） | 有 `opacity 0→1` |
| 窗口装饰 | 保留原生标题栏 | `setImmersiveChrome(true)` 关掉 |
| 关闭之后 | 回到图片墙 | 退出应用（会话语义，必须保留） |

改动：
* `viewer.js` 新增 **唯一入口 `openFullscreen(index, source)`**，`source` 三选一：
  `{el}`（缩略图，最准）→ `{rect}`（打开方式记录的那格）→ `null`（中心 0.8 兜底）。
  `openLaunch()` 降级为它的一个调用者。
* **删掉 `options.fadeIn` 开关**，`opacity: [0,1]` 写进 keyframes —— 从代码上杜绝
  「某条路忘了传」。（这是最有效的一刀：选项自由度越大，入口越容易分岔。）
* `viewer` 加 `onClosed` 回调（`finishClose` 里，`onExit` 之外另开一条），宿主据此
  恢复窗口形态 + 焦点。
* `main.js`：`openFullscreen()`（模块级）负责「先切形态 → 等 2 帧 → 开场 → 交焦点」；
  `useImmersiveChrome()` 用 `hasNativeChrome` 记账去重（形态没变就不发 IPC）。
  `bootLaunch` 里也要提前记账 —— 后端 `apply_immersive_window` 已经把装饰去掉了。

用户选了「连标题栏也一起统一」，所以有这一层临时切换。代价：每次开关预览会各发一次
`set_decorations`，已有去重；macOS 上切换窗口装饰会有一次重绘。无装饰不难拖动窗口 ——
`.viewer-bar` 里本来就有 `data-tauri-drag-region`。

测试：
* 新建 `tools/check_preview_entry.mjs`（`npm run test:entry`，已进 `npm run check`）：
  入口唯一、时长/缓动/背景是同一份常量、会话差异只落在窗口形态上。
* `ui/probe.html` 第 18 节比对**真正传给 `animate()` 的实参**（静态检查只能看到有没有
  这个方法，看不到调用时传了什么）：两条路的 from/to/opacity/duration/easing/bg 逐项相等。
* 探针 §11.5 的旧断言按字面找 `setImmersiveChrome(true)`，收敛进 `useImmersiveChrome`
  之后必须改写 —— 换成「只有一处真正调用后端命令」+「切形态排在开场之前」+「关闭后恢复」。

验证：`npm run probe` 222/222 ×2 尺寸；`npm run check` 全绿（cargo 零告警）。

### 教训
* **「统一两条路」的第一步是列出差异表**，别直接动手。这次列完才发现并不是两套实现，
  真正该改的是「几条调用约定」，改动量比预想小得多。
* 删掉一个 options 开关（把值写死）比新增文档说明有效得多：冗余的自由度就是分岔的入口。
* 探针里的 `main.js` 字面断言很脆 —— 一旦把调用收进一个包装函数（哪怕语义更强）就会
  假失败。这类断言要抓「约束」（谁排在谁前面、有几处调用）而不是「字符串」。
