# 2026-10-31

## 预览从「窗口内沉浸 / 最大化」升级为「操作系统级全屏」

用户要求图片墙单击与右键「打开方式」共用同一套全屏预览，且必须是覆盖任务栏 /
菜单栏 / Dock 的整屏，而不是窗口最大化。

### 关键结论：为什么 `maximize()` 不够
- `maximize()` 只铺满「可用工作区」，Windows 任务栏、macOS 菜单栏与 Dock 全都还在。
- 真全屏要 `window.set_fullscreen(true)`：Windows 盖任务栏、macOS 进独立 Space、
  Linux 交给 WM。

### macOS 的坑（务必记住，失败是完全静默的）
AppKit 只让 `collectionBehavior` 含 `NSWindowCollectionBehaviorFullScreenPrimary`
的窗口响应 `toggleFullScreen:`。**tao 从不设置它**（源码里搜不到
`setCollectionBehavior`），而预览必须去装饰 → 变成 `NSBorderlessWindowMask` →
`set_fullscreen(true)` 既不报错也不生效。解决办法写在 `src-tauri/src/macos.rs`：
用 objc2 遍历 `NSApp.windows()` 补上该标记（拿不到 MainThreadMarker 就静默返回）。
依赖 `objc2` / `objc2-app-kit` 是 macOS-only target dependency，与 tao 同版本，
无额外编译成本。

### 前端形态切换收敛为一个入口
`main.js` 里 `useImmersiveChrome()`（只管装饰）升级为 `useImmersiveStage()`：
同时做「去装饰 + 真全屏」并记账去重。四个调用点（图片墙点击/回车、Opened 事件
分支、冷启动降级、关闭恢复）全走它。新增 `noteStage()` 只改记账不发 IPC ——
「打开方式」的形态是后端 `prepare_launch_window` 趁窗口藏着拨到位的。
顺序：`进 = 先去装饰再全屏`，`退 = 先出全屏再还装饰`（反过来 macOS 会抖）。

### 其余
- `launch.js::launchWindowRect()` 从 `availWidth/availHeight` 改为整块屏
  `screen.width/height`；新增 `viewportFillsScreen()`，用它替代原来死板的
  「比较 target 尺寸」，因为全屏不是同步生效的（旧的 `nextFrames(2)` 不够）。
- Rust `prepare_launch_window` 现在返回 bool（是否真拿到全屏）；
  `maximize()` 只剩「全屏失败时的兜底」这一处。
- 校验：`check_boot.mjs` 增补「形态：操作系统级全屏」一节；`check_preview_entry.mjs`
  增补「窗口形态只有一个切换函数」；probe 223/223（桌面 + 窄屏）。
- README 新增「预览要的是操作系统级全屏，不是最大化」小节，含 macOS Space
  过场动画（约 0.3~0.5s）的权衡说明与退回 maximize 的做法。

## 修复「退出预览后标题栏回不来」+ 转场动画优化

### 根因（结论：次序问题，且窗口层静默丢弃，我们自己的记账还被污染）

tao 0.37.2 macOS `window.rs::set_decorations()` 第 1308 行起：

```rust
if decorations != self.decorations.load(Ordering::Acquire) {
    self.decorations.store(decorations, Ordering::Release); // ← 先记账
    let fullscreen = shared_state_lock.fullscreen.is_some();
    if fullscreen { return; }                                // ← 再丢弃，不生效
    ...
}
```

而 `set_fullscreen(false)` 只是发请求，窗口还要播 ~0.3~0.5s 转场；期间
`shared_state.fullscreen` 仍是 `Some(...)`（要等 `windowDidExitFullScreen:` →
`restore_state_from_fullscreen()` 才清空，而后者又把保存的 Borderless 样式写回）。
四步合起来 = 装饰永远恢复不了，而调用方记账里写着「已恢复」，之后再调也被
「已经是了」挡掉。**这类故障界面上毫无症状，只能靠读窗口层源码定位。**

关键事实（已验证到源码）：
- `tauri::WebviewWindow::is_fullscreen()` → `tauri-runtime-wry` `WindowMessage::IsFullscreen`
  → `window.fullscreen().is_some()`，读的正是 tao 那份只在转场结束后才清空的状态。
  **所以 `is_fullscreen()==false` 就是「转场播完了」的可靠信号。**
- `set_decorations` 与 `restore_state_from_fullscreen` 都用
  `DispatchQueue::main().exec_async()`（util/async.rs），**主队列 FIFO** —— 只要我们的
  调用排在其后，就一定生效。

### 修复
- Rust 删掉 `set_fullscreen` / `set_immersive_chrome` 两条命令，合并为唯一一条
  `set_stage(enabled)`：进 = 去装饰→全屏；退 = 出全屏 → **轮询 `is_fullscreen()`
  直到真的退出** → 才还装饰。等待跑在 `spawn_blocking` 里，2.5s 超时兜底。
- 新增 `window_stage` 命令返回真实 `{fullscreen, decorated}`，供前端对账。
- 前端 `useImmersiveStage()` 改为**串行队列 + 取排队时的最新意图**（原来并行跑会
  读到未更新的记账而直接 return，快速连按 Esc 就把形态搞乱）；切换前先对一次账；
  失败按「没切成」记账以便重试。

### 转场动画：三段式「幕后换场」
退出那一下跳动的根因也是次序：以前是「播动画 → 撤遮罩 → 切形态」，窗口缩回与
网格重排全在用户眼前。改为 ① 画面退场（背景**保持不透明**）→ ② `onBeforeClose`
钩子幕后换场 → ③ 根容器淡出。
**坑**：淡的必须是**根容器**而不是 `.viewer-backdrop` —— 根容器自带不透明背景
（`--viewer-bg` 是实心色），只淡背景层底下还是黑的，以前是靠 `root.hidden=true`
硬切掉的。
统一常量：`EASE`（位移）/ `TWEEN_FADE_EASE`（转场透明度，**别和控件层的
`FADE_EASE` 弄混**）/ `OPEN_MS=300` / `CLOSE_MS=240` / `CURTAIN_MS=180`。
支持 `prefers-reduced-motion`（跳过 FLIP，压到 `REDUCED_MS=120`）；`will-change`
只在转场期间挂；`viewer.prime()` 幕布掩盖切全屏那段等待。

### 新增工具与校验
- `tools/check_syntax.mjs`（`npm run test:syntax`，已入 `check`）：把每个 js 复制成
  `.mjs` 交给 `node --check`。**其余检查器全是正则匹配文本，看不见「文件解析不了」**
  —— 本次 `FADE_EASE` 重名就是靠探针才发现，补上后几毫秒就能挡住。
- probe 新增 §19（真的跑一次关闭，在钩子那一刻拍下 `root.hidden` / `backdropOpacity` /
  `slide.style.opacity`，断言「换场时遮罩还在」）与 §20（减少动态效果、will-change）。
- 结果：`npm run check` 全绿；`npm run probe` 桌面 + 窄屏各 **232/232**。

## 修复「退出预览后页面卡死」（ESC / 关闭按钮 / 点空白 三种全中）

### 根因：不是"忘了卸载"，是"卸载排在了一串不一定会兑现的 await 后面"

关闭流程原为 `播退场动画 → await 幕后换场(切回窗口形态) → 撤幕布 → finishClose()`。
`finishClose()` 才 `root.hidden = true`。而"幕后换场" =
`IPC → 后端轮询等全屏转场 → 等两帧布局`。**任一环不兑现 → 那层
`position:fixed; inset:0; z-index:200` 的不透明预览永远盖在屏幕上** →
点不动、滚不了，和死了没区别。

不兑现不是假设：**rAF 在窗口全屏转场 / 最小化 / 切到另一个 Space 时会停，
且不通知任何人**。`await nextFrames(2)` 就成了没有日期的船票。
更糟：形态切换走**串行队列**，一次挂起会堵死后面所有调用。

### 复现方法（关键：探针覆盖不到）
`ui/probe.html` 里 viewer 是探针自己 new 的，走 `viewer.open()`，**不经过**
宿主的 `useImmersiveStage` / `prime()` / `onBeforeClose`。所以"探针 232/232
全绿"和"真机卡死"可以同时成立。
→ 新建 `ui/exit_probe.html` + `tools/check_exit.mjs`（`npm run test:exit`）：
加载**真实的 main.js**，注入可记录的假 `__TAURI_INTERNALS__`（只给
`picshow://items` 投喂；给 open-file 投喂会误走"打开方式"会话并给 body 加
`is-immersive`，从而让 `.grid{display:none}` — 那正是"无法滚动"的另一种成因）。
跑 3 种退出 × 3 轮 + 连按 Esc + 快速连击 + 幕布期取消 = 68 项。
**无头环境 rAF 根本不回调（frames=0），恰好等价于真机的帧停摆**，所以这个
环境天然就是最严苛的测试台。

### 修复（原则：让"卸载预览层"不依赖任何异步的成败）
- 新增 `ui/js/async.js`：`withTimeout()` / `nextFrames()` / `waitFor()`，
  **每个等帧函数都同时挂 setTimeout 兜底**。这是根治点。
- `viewer.js`：`close()` 把 `finishClose()` 放进 `finally`；`finishClose()`
  加幂等守卫 `if (!this.isOpen && !this.closing) return;`；新增
  `prepareBackstage()` 只等 `BACKSTAGE_MS=1200`；幕布加 4s 保险丝；
  `open()` 被拒时摘幕布；**幕布期间 Esc = 取消这次打开**（那时 isOpen=false，
  关闭分支不认，只能由幕布自己响应）+ `onOpenCancelled` 回调；
  新增 `destroy()`（拆 RO 与全局 keydown/resize）。
- `main.js`：队列每环 `withTimeout(runStage(), 5000)`，IPC 各 3000；
  等的过程中 `wantedStage` 变了就提前让位；`openFullscreen` 前先问
  `viewer.canOpen`；用 `openSeq` 世代号作废还没落地的 open()。
- `strip.js`：加 `destroy()`。

### 教训
- **"有没有写收尾"静态上看着永远是成对的**，真正的区别是中间隔了几段
  「不一定兑现」的 await。要用 `finally` + 超时，而不是靠调用顺序。
- 新增 `tools/check_unload.mjs`（`npm run test:unload`）把"收尾在 finally、
  幂等、每段 await 有超时、等帧有兜底、幕布有保险丝、队列不会被毒化"写成断言。
- 反向验证：把 async.js 的 setTimeout 兜底临时去掉 → 测试 8 处失败，
  "形态只进不出"（进=3 出=2），确认这套断言真能抓住原 bug。

## 修复「退出预览后窗口不还原（看似停在最大化）」

### 定位手段：临时几何探针（不靠猜）
在 `lib.rs` setup 里挂一个 `PICSHOW_STAGE_PROBE=1` 才启动的线程：show → 记录
几何 → `apply_stage(true)` → `apply_stage(false)` → 每 100ms 采样 16 次，
打印 `inner/outer/pos/max/fs/deco`。测完已删除。
走一遍就够排除大半猜测；**macOS 窗口行为必须实测，源码读不出来。**

### 实测到的关键时序（本机 3840×2160 物理屏，dpr=2）
退出全屏后 macOS **约 500ms 还要再摆一次窗口**（补上标题栏那一笔），分两段：
```
+100~400ms  inner=1800x1200 outer=1800x1256 @ (400,300)   ← 标题栏刚挂上去（中间态）
+500ms起    平台自己的最后一笔落地，之后不再变化
```
对照实验（保留等待、强制不写回）给出的结论：
- 起始为普通窗口 → 平台自己收尾是对的，最终稳定在起点 (400,300)；
  **但我们若在这 500ms 内写 set_size/set_position，它那一笔会以我们写的值为
  基准再偏 56px（一整条标题栏），偏差被永久钉死（实测落在 (400,356)）。**
- 起始为最大化（zoom）→ 平台自己还原是**错的**：3840x2110@(0,50), max=true
  变成 3840x2054@(0,106), max=false。这条必须人工校正。

所以：**先等平台摆完，再决定要不要出手** —— 顺序反了就是负优化。

### 根因
`set_stage` 从来只管「全屏 / 装饰」这两项，**几何没有任何地方记录，也没有任何地方还原**：
- `go_fullscreen()` 的 `maximize()` 兜底一旦走到，全项目没有一处 `unmaximize()`
  （不可撤回）；
- 最大化起始那条路平台自己就还原错（tao 在 `windowWillEnterFullScreen` 用
  `isZoomed()` 记账，而我们对无边框窗口已经踩中它的启发式退化判断）；
- 另外 `tauri::set_size()` 设的是**内容区**，若拿 `outer_size()` 去喂它，
  每进出一轮窗口就长高一截标题栏，几轮后正好顶满屏——观感就是「一直是最大化」。

### 修复（后端单点，最小改动）
- `model.rs` 加 `WindowRect{ size, position, maximized }`；`state.rs` 加槽位
  `remember_stage_rect()`（**已有则不覆盖**，嵌套进入取到的才是最早那份浏览态）
  / `take_stage_rect()`。
- `apply_stage(true)` 第一行就 `capture_window_rect()`（**必须在去装饰 / 切全屏之前**）。
- `apply_stage(false)`：还装饰 → `restore_window_rect()`（三条退出路径的唯一合流点）。
- `restore_window_rect()`：`wait_until_settled()`（连续两次采样一致才算稳，
  macOS 门槛 650ms / 其它平台 0，上限 1.5s）→ 一致就**一笔都不写** → 不一致才写，
  写完短等 150ms，最多 3 轮。最大化交给 `maximize()`，非最大化先 `unmaximize()`
  再 `set_size` + `set_position`。
- 单位必须对称：`inner_size()` ↔ `set_size()`、`outer_position()` ↔ `set_position()`。
- 实测耗时：`set_stage(false)` 普通 660ms / 最大化 836ms，都在前端
  `BACKSTAGE_MS=1200` 预算内（藏在幕布后面，用户看不见）。

### 前端（只补残留，不碰逻辑）
`viewer.finishClose()` 额外清 `is-idle` 与 `is-origin-hidden`（兜住 `playClose()`
提前 return 的路径）。**没有任何 body 溢出锁定、没有页面级 maximized 替身类。**

### 校验
- 新增 `tools/check_stage_restore.mjs`（`npm run test:restore`，26 项，已入 `check`）：
  快照位置 / 单位对称 / 单点还原 / 三路径同收敛 / 清理无残骸。
  反向验证：删掉关键行 → 6 处报错，还原即通过。
- `check_boot.mjs` 里「maximize 全局唯一」改为「只允许兜底 + 原本最大化的还原两处」。
- `npm run check:all` 全绿：静态全通过、exit probe 69/69、gallery probe 234/234×2。

## 修复「退出预览后停在最大化 + 标题栏消失」（上一版没生效，重新定位）

### 上一版为什么没生效：还原代码**根本没被调用**
上一版后端还原逻辑是对的（真机探针验证过），但**只测了 `apply_stage` 本身，没测前端那段对账**。
真实链路里 `runStage()` 开头先跟后端对账：

```js
isStageFullscreen = real.fullscreen;          // ← 只看这一个字段
if (enabled === isStageFullscreen) return;    // ← 于是退出被整个跳过
```

全屏被平台拒收时后端退化为 `maximize()`，`fullscreen` 恒为 false →
`enabled(false) === isStageFullscreen(false)` → **直接 return，还原永不执行**。

### 定位手段：把前端逻辑一起复刻进探针（关键改进）
上一版探针只调 `apply_stage()`，绕开了前端，所以永远测不出这个问题。
这次探针**把 `window_stage` 对账 + 早退那条 if 一起复刻**，并加
`PICSHOW_PROBE_MAX=1`（强制走 maximize 兜底）/ `PICSHOW_PROBE_STARTMAX=1`（起始即最大化）。
一遍就打出了原样复现：

```
start:      2400x1600 @ (600,400) max=false deco=true
in-preview: 2400x1600 @ (0,50)    max=true  deco=false   ← 兜底 maximize
exit 对账:  fullscreen=false
exit: SKIP <<<< 还原根本没有被调用
exit+2000ms:3840x2110 @ (0,50)    max=true  deco=false   ← 与用户报告完全一致
```

**教训：窗口形态类缺陷的探针必须复刻前端决策，不能只测后端函数。**

### 两个根因（都在入口层，不在退出处）
1. **前端对账判据太窄**：只盯 `fullscreen`，漏掉「无标题栏」和「被最大化兜底」。
2. **全屏能力标记从来没生效过**：`mark_fullscreen_capable()` 内部要
   `MainThreadMarker`，而 `set_stage` 跑在 `spawn_blocking` 线程 → 日志里永远是
   「不在主线程，跳过全屏能力标记」。于是无边框窗口拿不到
   `NSWindowCollectionBehaviorFullScreenPrimary`，`set_fullscreen(true)` 被拒收
   → 走 `maximize()` 兜底 → 而兜底那一步当时没有任何代码负责撤回。

### 修复
- `commands.rs::go_fullscreen(app, window)`：标记改由
  `app.run_on_main_thread(mark_fullscreen_capable)` 投递到主线程（两条消息进同一
  队列，先投的先执行，所以一定排在 `set_fullscreen` 之前）。实测日志从「跳过」
  变成「已补上 FullScreenPrimary」。
- `macos.rs`：`window.collectionBehavior() | FullScreenPrimary`，只补一位，
  不整体覆盖（否则抹掉「跟随 Space」等默认位）。
- `model.rs`：`WindowRect` 退成纯几何；新增 `StageSnapshot{decorated, maximized, rect}`；
  `WindowStage` 增加 `maximized` 供前端对账。
- `state.rs`：`stage: RwLock<Option<StageSnapshot>>`（`remember_stage` / `take_stage`，
  已有不覆盖）+ `stage_fullscreen: AtomicBool`（这次是不是真进过全屏）。
- `commands.rs::apply_stage`：
  - 进：快照排最前 → 只在原本有装饰时才摘 → `go_fullscreen` → 记 `stage_fullscreen`；
  - 出：`set_fullscreen(false)` → `let exited = wait_fullscreen(false)` →
    `restore_stage(app, &window, exited)`。
- `commands.rs::restore_stage`：
  1. 装饰：快照说有就补；**`exited` 为假时不写**（tao 会丢弃并把记账改成
     「已恢复」，从此再也补不回来）；无快照时按「有」补，避免永久无边框；
  2. 只在实际进过全屏时才 `wait_until_settled(650)`（兜底路径等它纯属白等）；
  3. `stage_matches → write_stage`，最多 3 轮；原本最大化交还 `maximize()`，
     否则先 `unmaximize()` 再 `set_size` + `set_position`。
- `main.js::runStage`：判据改成
  `real.decorated === false || real.fullscreen === true`；
  进入后一律 `isStageFullscreen = enabled`（不再用回执 `accepted`）。
  **不能把 `maximized` 也算进判据** —— 用户自己放大浏览窗口是合法的，
  那会让「点图进预览」被误判成「已是预览形态」而不切形态。

### 两个实测出来的坑（都是猜不出来的）
- **`inner_size()` 在 zoom 刚结束时读到的是动画前的陈旧值**：实测 outer 已经是
  3840×2110 了，inner 还报 2400×1544。所以「最大化」这一路**只能核对 zoom 状态
  本身**，拿尺寸比对会永远不收敛，然后反复 unmaximize/maximize 把窗口折腾到意外尺寸。
- **`unmaximize()` 紧接着 `maximize()` 会被 zoom 动画合并掉**，最后停在退出来的
  尺寸上（连写三轮都一样）。所以这条路最终改成「只 maximize，不先退」。

## 重写：判定「运行时切换窗口装饰」这条路根本走不通，改为「装饰永不变」

### 上一版为什么还是没生效
前一版修的是**前端对账判据**（把 `decorated` 也算进「预览形态」）。判据改对了，但
**底层仍然在运行时摘装饰**，所以敌人还在：只要走过 `set_decorations(false)`，
macOS 窗口层就会在退出全屏时无条件把「无边框」写回来，我们补的那笔照样被覆盖或
被闸门变空操作。**改判据只是让还原「被调用」，没让它「起作用」。**

### 决定性的源码事实（tao 0.37.2，macOS）
```
util/async.rs:114 toggle_full_screen_async
    let curr_mask = ns_window.styleMask();        // 我们已摘标题栏 → 无边框
    if !curr_mask.contains(Titled | Resizable) {
        set_style_mask(Titled | Resizable);       // 临时加回来
        shared_state_lock.saved_style = Some(curr_mask);   // ← 记住「无边框」
    }
    ns_window.toggleFullScreen(None);

window.rs:988 restore_state_from_fullscreen  ← windowDidExitFullScreen 回调
    shared_state_lock.fullscreen = None;
    let maximized = shared_state_lock.maximized;  // 进全屏时 is_zoomed() 记的
    let mask = self.saved_style(&mut ...);       // ← 无边框
    self.set_style_mask_async(mask);              // 无条件写回
    self.set_maximized(maximized);

window.rs:1308 set_decorations
    if decorations != self.decorations.load(Acquire) { ... }   // 「已经是了」就变空操作
```
→ **tao 的语义是「进全屏时什么样，出全屏就什么样」，与产品需求「进前摘、出后补」
正好相反。两笔写入排在同一个 `DispatchQueue.main` 的 FIFO 里，纯竞态，靠「等 N
毫秒再写」卡顺序卡不住。**

### 决定性实验（探针跑完已删除）
**不碰装饰、只切全屏，macOS 自己还原得又快又准：**

| 场景 | 进入前 | 退出后 |
|---|---|---|
| 普通 1200×800 | 2400×1600 @ (720,178) max=false | 同左，**逐项精确** |
| 起始最大化 | 3840×2110 @ (0,50) max=true | 同左，**逐项精确** |
| 加 FullSizeContentView + 透明标题栏 | 同上两种 | 同样零偏差（styleMask 32783 → 32783） |

且 **200ms 内即落定**（此前「等 650ms」的整套等待逻辑是针对「摘装饰」这条
错路打的时间补丁，路一换就全不需要了）。

### 新方案：装饰永不变，进出预览只切全屏
- **启动时一次性**给窗口设：`FullSizeContentView` + `titlebarAppearsTransparent(true)`
  + `titleVisibility = Hidden`，**保留 `Titled`**（交通灯靠它）。此后任何路径都不再
  改窗口样式。
- 保留 `Titled` ⇒ AppKit **自动授予** `FullScreenPrimary` ⇒ 旧的「补能力标记」
  那段代码连同它「不在主线程被静默跳过」的坑一起删除。
- 沉浸式的观感由前端 `.viewer-bar` 实现（本来就是唯一标题栏）。
- 删除 `go_fullscreen` 的 `maximize()` 兜底 —— 那是**没有撤回路径**的一步。
- 几何与最大化交给 AppKit 自己还原（它本来就负责，而我们不动 styleMask 时它
  记的账是准的）。

顺带修掉一个必然复现的坑：`is_zoomed()` 对无边框窗口退化成「框架是否等于屏幕
可视区」的启发式判断，摘标题栏后必中 ⇒ 记账失真 ⇒ 退出被留在最大化。不动
styleMask 就根治。
