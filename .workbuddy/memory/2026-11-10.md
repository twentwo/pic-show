## 修复：全屏预览「画廊点击预览失败 / 切换后不显示目标图片」

- **为什么之前一直没发现**：`ui/probe.html` 跑在 headless 里，`img://localhost/...`
  全部加载失败，288 条断言量的是几何、索引、状态机，**从没量过「这一格到底
  有没有图、是不是目标图」**。这次先写独立真 DOM 复现探针（临时
  `ui/_repro.html`，已删）：patch `HTMLImageElement.prototype.src` 把自定义协议
  换成可加载的 SVG data URL，逐步读当前槽 `__low.__want` / `naturalWidth` /
  `parentNode` / computed opacity / counter，才量到 `jumpTo(0)` 后
  `slotOpacity:"0"`。后来把这套桩固化成 `ui/probe.html` 第 21 节。
- **根因一（`viewer.js::jumpTo`）**：inline 写 `slide.style.opacity='0'`，却用
  `fill:'none'` 播淡入且**从不提交终值** → 动画播完回到 inline 0，当前槽永久
  全透明。后续 `go()` 的 `rebalance()` 只填轮转出去那一格，当前槽不被 `fill()`
  碰到，透明一直残留 → 切换 / 连续切换张张空白，看起来像图片加载失败。
- **根因二（`viewer.js::fill`）**：`__index/__shown` 未变的提前返回跳过清 inline
  opacity，残留的 0 会带到「再次点击打开预览」与换页。
- **根因三（`jumpTo` 同索引）**：后端送来另一份图片集合、index 没变时直接
  return，画面停在上一份集合的旧图上。
- **修法（只在 `viewer.js`）**：淡入改 `fill:'forwards'` +
  `withTimeout(fade.finished, JUMP_MS+ANIM_SLACK_MS)` 里 `removeProperty('opacity')`
  再 `cancel()`；**提交不设世代号守卫**（终值是「可见」，新切换接管也不能跳过），
  **等待仍用原 `setTimeout(JUMP_MS)`**，交互时机不变。`fill()` 的清 opacity 提前到
  提前返回之前。同索引分支比对 `currentSlot.__low.__want` 与本次
  `thumbUrl(item.id)`，不一致才强制三槽重画。方向映射、索引边界、结算闸门、
  贴边 / 落位 / 回弹、原生相位、画廊点击入口全部一字未改。
- **同步**：`tools/check_preview_entry.mjs` 第 7 组（5 条结构断言）、
  `ui/probe.html` 第 21 节（`21.1~9`，克隆一份干净 Viewer + 图片桩，双视口）、
  README 新增「预览显示」小节与回归清单、`MEMORY.md` 写进「动画与像素」和
  「回归纪律」。顺手修正 `viewer-main.js` 上一轮收敛后遗留的
  「默认关闭 / `=1` 才装监视器」过期注释（仅注释，零行为改动）。
- **别回退的两点**：`open()` 淡入不写 inline 0（`fill:'backwards'`）；
  `playClose()` 有意写 0（防止画面冒出来），由 `resetSlots()` 收掉，可见性兜底
  不能把它清掉。
- **验证**：独立复现探针修复前 `jumpTo` 场景量到 `slotOpacity:"0"`（61/62，
  唯一失败项），修后扩到 8 个场景 78/78；固化后的正式回归 `npm run check`
  RC=0（0 个 ✗，含 cargo check）、`npm run probe` 双视口各 **297/297**
  （288+9）、`check_exit` **60/60**（首次与 probe 挤在一起偶发超时，单独重跑
  4.3s 通过，与代码无关）。反向变异三处（去掉终值提交 / fill 兜底退回提前
  返回之后 / 同索引不再重画）均被静态 1 处 + 真 DOM 双视口各 1 处共 3 处捕获，
  恢复后 `viewer.js` sha256 `4a8d44a5…` 逐字节一致、全套复绿。
- **真机观感仍待人工验收**：探针量的是 DOM 状态与数值，不替代肉眼看
  「打开 / 连续切换是否每次都显示当前图」。
